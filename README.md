# Grok Orchestrator (MVP)

Десктоп-приложение (Tauri v2, Rust) для управления множеством чатов с моделями через
Groq API, с ротацией нескольких API-ключей (разных аккаунтов) и тремя режимами
оркестрации между моделями + визуальным графом пайплайна.

## Возможности MVP

- **Множество чатов**, каждый со своим пайплайном моделей.
- **Пул API-ключей Groq**: добавляете сколько угодно ключей (разные аккаунты),
  бэкенд на Rust делает round-robin между ними и автоматически уходит на
  60-секундный "cooldown" тот ключ, который словил `429 Too Many Requests`,
  переключаясь на следующий доступный — это и есть обход rate limit.
- **Три режима работы** пайплайна (настраиваются на чат):
  1. **Цепочка (chain)** — вывод модели №1 становится входом модели №2 и т.д.,
     финальный ответ — выход последней модели.
  2. **Делегирование (delegate)** — все модели получают исходный запрос
     параллельно (каждая — с своим системным промптом/ролью) и их ответы
     собираются в одно сообщение.
  3. **Совместная работа (collab)** — все модели, кроме одной выбранной
     "модели-синтезатора", отвечают независимо, затем синтезатор сводит их
     ответы в единый финальный ответ.
- **Визуальный граф** пайплайна (SVG) — показывает узлы (модели) и связи между
  ними, топология зависит от режима (линейная цепочка / веер делегирования /
  звезда для совместной работы), с подсветкой узла, который сейчас
  выполняется (пульсация), выполнен (зелёный) или упал с ошибкой (красный).
- Все чаты, ключи и настройки пайплайнов сохраняются на диск
  (`app_data_dir/data.json`) и восстанавливаются при перезапуске.

## Важно про ключи

Ключи хранятся в открытом виде в `data.json` в папке данных приложения и в
памяти процесса — это MVP без шифрования. Не используйте это на общем
компьютере без понимания рисков. Для продакшена стоит добавить шифрование
(например, через `keyring`/OS keychain).

## Требования для сборки

- [Rust](https://rustup.rs/) (stable)
- Tauri CLI: `cargo install tauri-cli --version "^2.0.0" --locked`
- Системные зависимости Tauri для вашей ОС:
  - **Linux**: `webkit2gtk-4.1`, `libayatana-appindicator3`, `librsvg2` и т.д. —
    см. https://v2.tauri.app/start/prerequisites/
  - **macOS**: Xcode Command Line Tools
  - **Windows**: WebView2 (обычно уже есть в Windows 10/11) + MSVC build tools

Node.js **не требуется** — фронтенд написан на чистом HTML/CSS/JS без сборщика.

## Запуск в режиме разработки

```bash
cd grok-orchestrator
cargo tauri dev
```

## Сборка релизного бинарника

```bash
cargo tauri build
```

Готовые установщики появятся в `src-tauri/target/release/bundle/`.

Иконки в `src-tauri/icons/` — это временные плейсхолдеры. Перед релизной
сборкой замените их своими (можно сгенерировать через `cargo tauri icon
path/to/logo.png`).

## Структура проекта

```
grok-orchestrator/

│   ├── src/main.rs      # пул ключей, ротация/failover, вызов Groq API, персист

    ├── style.css
    └── app.js           # состояние, пайплайны, рендер графа, оркестрация
```

## Как использовать

1. Запустите приложение, добавьте в сайдбаре один или несколько ключей Groq
   (кнопка "Добавить ключ") — можно с разных аккаунтов.
2. Создайте чат ("+ Чат"), выберите режим (Цепочка / Делегирование /
   Совместная работа) в шапке чата.
3. Нажмите "⚙ Пайплайн" — добавьте нужные модели-узлы, задайте каждому имя,
   ID модели Groq (например `llama-3.3-70b-versatile`) и системный промпт
   (роль узла). Для режима "Совместная работа" выберите модель-синтезатор.
4. Отправляйте сообщения — граф слева покажет, какой узел сейчас работает.

## Известные ограничения MVP (что можно улучшить дальше)

- Делегирование сейчас не автоматически "нарезает" запрос на аспекты —
  каждая модель получает весь исходный текст и отвечает согласно своей роли
  (заданной системным промптом). Автоматическое разбиение задачи на подзадачи
  — хорошее следующее улучшение (например, отдельным LLM-шагом "роутером").
  Также в собранном ответе делегирования удобно добавить сообщение об
  ошибке в конкретном шаге, а не просто общую ошибку.
- Совместная работа делает только один "раунд" обмена мнениями перед
  синтезом (без итеративного обсуждения между моделями).
- Ключи хранятся без шифрования (см. раздел выше).
- Список моделей Groq в подсказках может устареть — Groq периодически
  меняет доступные модели, вводите актуальный ID вручную при необходимости.
